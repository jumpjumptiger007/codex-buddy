# Codex Buddy R0 Reuse Audit

This is the evidence appendix for the authoritative [vNext architecture and R0–R7 roadmap](codex-ambient-dashboard.md). The architecture document owns the final target decisions and gate scopes; this appendix records pinned sources, provenance, module-level comparison, and evidence limits. R0 copied no donor production source, binary, or asset into codex-buddy.

## Audit method

The current workspace was checked at commit f12a6e0 on main with a clean working tree before documentation edits. Current code and tests take precedence over donor claims. Public donor repositories were acquired read-only into a temporary directory outside the workspace and pinned to full commit SHAs. No donor remote, submodule, dependency, source file, generated file, or asset was added to the project.

Evidence hierarchy:

1. Current project source, headers, tests, BSP contracts, and build targets.
2. Exact source and license text at each pinned donor commit.
3. File-blob identity and commit history when available to establish lineage.
4. Donor READMEs only as navigation and capability claims; they do not establish correctness, security, hardware compatibility, or a license.

A license at one repository root is not assumed to cover separately sourced artwork, fonts, models, audio, bundled firmware, compiled WASM, or vendored dependencies. REUSE DONOR and ADAPT DONOR require positive source and license evidence for the code in question. The decision column below uses only the four values KEEP OURS, REUSE DONOR, ADAPT DONOR, and DROP. Provenance and uncertainty are separate evidence fields.

## Provenance and lineage findings

- S2's pinned tree has no root LICENSE. Its parent repository's S1 MIT license does not, by itself, settle the licensing of code added only on S2. No S2-only implementation is copied or approved for reuse.
- S2 and S3 contain 36 byte-identical file blobs at the same paths, including main/buddy_ble_lifecycle.c and .h, main/buddy_ble_store.c and .h, main/buddy_character.c and .h, main/buddy_line.c and .h, main/buddy_i4.c and .h, and several matching tests and controller files. This establishes exact content overlap. The shallow S3 snapshot does not establish the direction of transfer or shared Git ancestry, so the audit does not claim which repository authored the overlapping files. Where a later candidate comes from S3, its S3 MIT license and NOTICE are the reuse evidence; the S2 snapshot is not used as the license basis.
- S4 and S6 contain 11 byte-identical same-path blobs, including src/ble_bridge.cpp, src/ble_bridge.h, src/buddy_common.h, REFERENCE.md, and shared serial/character tools. S6 has no root license. Use S4 as the identifiable licensed source for any protocol reference; do not attribute S6's other implementation to S4 or reuse it without its own license evidence.
- S3's source-level Hook and desktop Python modules are not identical at those paths to S2. Their candidate license is S3's root MIT, with S3's notice obligations retained if portions are reused.
- S7's NOTICE provides an explicit upstream ancestry commit. This audit inspected S7's AI Passport board, settings, button, battery, and audio service source, but did not copy its application framework, generated resources, cloud behavior, or third-party model/audio assets.
- S8 is a useful browser-side ESP32-C3 firmware and input simulator, but it does not implement or validate the Passport's real BLE security, radio behavior, or host pairing.
- S9's MIT license does not turn its bundled characters into safe product assets. Its asset policy is a provenance reference only; no pet package or image was adopted.

## Resource and evidence limits

R0 does not establish radio range, throughput, battery life, pairing UX, MIC/Speaker quality, audio latency, current free heap, stack high-water marks, frame limits, exact UUIDs, MTU, or queue sizes. Donor defaults are source facts about those donor builds, not measurements for this board.

### Historical Gate 0 observations carried forward

These observations were recorded by the superseded architecture document. R0 preserves them as historical evidence; it did not rerun the probes, broaden the scanned corpus, or convert them into claims about all current Codex behavior.

- A metadata-only rollout scan did not observe the event names `SessionConfigured`, `TurnStarted`, or `TurnComplete`. A follow-up found 46 persisted `event_msg` records with `payload.type = turn_aborted` across 32 rollout files. Their envelope fields were `type`, `ordinal`, `timestamp`, and `payload`; the inspected abort payloads had `type`, `turn_id`, `reason`, `started_at`, `completed_at`, and `duration_ms`. Each inspected file had one `session_meta.payload.session_id`; ordinals increased within those files, and activity overlapped across distinct sessions. This sample justified accepting only the verified abort form in the then-current watcher; it does not establish the complete production Hook contract.
- Persisted `rate_limits.primary` and `rate_limits.secondary` records contained source-provided usage and reset values for 300-minute and 10080-minute windows. An App Server `account/rateLimits/read` comparison was unavailable because no safely callable transport/request framing had been established; no request was sent. No token-based estimate was used.
- A metadata-only scan of the then-available rollout event/type labels found no matching permission, approval, trust, policy, sandbox, `allowed`, or `denied` signals. The scan was limited to that corpus and does not prove that permission behavior is absent.
- Composer Accessibility was marked `NOT_INSPECTED`: the available accessibility hierarchy call could return text and had no metadata-only filter. No TCC prompt or setting change was triggered. Composer selection, editability, and insertion remain unverified.
- A local STT comparison was unavailable because no supported `whisper.cpp` runtime or pre-existing `base`/`small` model pair was found in the checked locations. No model was downloaded or run, and no user audio was used.

R1/R2 must collect current, consented evidence for the production source and adapters they implement. Historical probe results do not replace that work.

The audit confirms source and license facts only at the pinned snapshots listed above. It does not give legal advice, validate runtime behavior on every supported host, or grant rights to unlisted assets and dependencies.
